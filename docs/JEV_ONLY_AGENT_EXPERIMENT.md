# JEV-Only Agent Experiment

Status: experimental MVP  
Branch: `experiment/jev-only-agent`  
Base: `experiment/jev-agent-architecture` at `cfd6509139f1f880e7c4413f74266dd150a5e5e9`

## Purpose

Test whether AIRI can achieve bounded Factorio goals with Jev as the only AI model.

Jev does not replace Autorio or the deterministic harness. The experiment keeps:

- Factorio as world truth;
- deterministic observations;
- runtime-generated candidate values;
- operation schemas and parsing;
- preflight and physical/safety enforcement;
- actor/session/epoch identity;
- operation receipts;
- persistence and lifecycle;
- deterministic completion where available.

The experiment removes the generative Main LLM from the active decision path.

The core loop is:

```text
user goal
  -> deterministic observations
  -> deterministic candidate generation
  -> Jev selects one complete candidate
  -> normal parser / preflight
  -> Autorio executes
  -> authoritative receipt / world state
  -> repeat
```

If the next decision is not represented by the finite candidate space, the runtime must
fail closed with `jev_only_unsupported_decision_space`. It must not silently wake the
Main LLM.

## Runtime switch

```text
SGLUNA_REASONING_MODE=llm_jev   # existing architecture
SGLUNA_REASONING_MODE=jev_only  # this experiment
```

`jev_only` requires the Jev / TypeSafe decision provider. Main-LLM credentials are not
required and the runtime installs a throwing Main-LLM provider stub so accidental fallback
is visible as a bug.

## MVP capability

The first vertical slice is exact navigation.

1. The harness reads nearby live entities.
2. Only entities with authoritative Factorio `unit_number` identities enter the candidate set.
3. Each candidate is a complete `walk_to_entity_exact` operation with an actor/epoch freshness token.
4. Jev receives the user's goal and bounded descriptions of those complete candidates.
5. Jev selects one candidate.
6. Existing typed-projection confidence policy, operation parsing, preflight, and Autorio execution remain in force.
7. Low confidence, provider failure, no candidates, or a non-executable Jev route fails closed.

This slice is intentionally small. It proves the architecture, not general Factorio autonomy.

## Finite candidate frontier

The experiment should grow by adding deterministic candidate generators, not by granting
Jev free-form operation or plan generation.

Recommended expansion order:

1. **Navigation**
   - exact observed entities;
   - runtime-generated positions / placement anchors.

2. **Resource acquisition**
   - engine-discovered resource patches;
   - mineable products;
   - bounded quantity brackets generated by code.

3. **Crafting**
   - current-force recipes;
   - craftable outputs from live inventory and recipe dependencies;
   - bounded quantity brackets.

4. **Research**
   - currently available technologies;
   - deterministic prerequisite frontier.

5. **Construction**
   - runtime placement candidate sets;
   - complete `place_candidate` operations only;
   - construction-plan candidates generated by code/skills.

6. **Logistics / machine configuration**
   - exact observed entities;
   - valid recipes, item transfers, belt/inserter relationships and capacity choices derived from runtime facts.

7. **Reusable skills**
   - finite applicable skill candidates;
   - each skill expands into another bounded candidate space rather than prose instructions.

8. **Strategic frontier**
   - dependency-graph nodes and Roadmap-level objectives derived from current goal/world state;
   - Jev chooses which grounded frontier node to pursue next.

## Design constraint

Candidate generation should be engine-, graph-, and skill-derived whenever practical.
Do not encode one script per Factorio scenario.

A useful test for every new candidate generator is:

> Can this generator be reused for many goals because it enumerates what the current
> world and rules permit, rather than because it recognizes one hand-authored scenario?

## Success criteria for the next milestone

The next meaningful milestone is a resource/crafting loop that can satisfy a small
inventory goal with no Main-LLM call:

```text
goal -> inspect inventory -> choose missing dependency -> gather/harvest -> craft
     -> re-check authoritative inventory -> close when satisfied
```

A good first E2E target is a small early-game item whose recipe and raw-resource path are
fully engine-discoverable. The test must record Main-LLM calls as zero and must fail closed
when no candidate represents the required next step.
